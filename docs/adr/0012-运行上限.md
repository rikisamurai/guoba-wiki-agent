# 0012 每次运行的硬上限：40 Step / 15 分钟 / $1

- 状态：已接受
- 日期：2026-11-02

## 背景

0007 的修正回路最多 3 次，但模型可能在其他环节反复调用工具（例如反复 grep、反复改同一文件）。按 0011 的 `deepseek-flash` 粗算，一次 ingest 约 25 轮、$0.1–0.2。

## 决策

每次运行同时受三个上限约束，默认值：

| 上限    | 默认值  | 计量方式                                                        |
| ------- | ------- | --------------------------------------------------------------- |
| Step 数 | 40      | 每次模型请求算一个 Step（Pi 称为 turn），在 `finishTurn` 中计数 |
| 时长    | 15 分钟 | 从运行开始计时，超时调用 `agent.abort()`                        |
| 费用    | $1      | 每轮结束时按 Pi 返回的 Usage 和模型价格累加                     |

- 任一上限触发：中止运行，判为失败。可以查看 Staging 的 diff，但不能 Apply。
- 三个值都可以在配置的 `tasks.<name>.limits` 中覆盖。
- 运行结果中要写明停止原因：完成、Invariant 失败、触及某个上限、用户取消、provider 错误。

## 影响

- 默认值约为预期用量的 1.5–5 倍，正常运行碰不到。
- 费用依赖 Pi 的 Usage 与内置价格表；provider 没有返回 Usage 时按 0 计，同时在结果中标注“费用未知”。
- 换成 `deepseek-v4-pro` 时，$1 的上限可能偏紧，需要在配置中调高。
