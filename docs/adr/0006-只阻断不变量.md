# 0006 代码只阻断不变量，其余 Skill 规则只提示

- 状态：已接受
- 日期：2026-11-02

## 背景

0004 规定自然语言规则以 Skill 为准，0005 让 Agent 按 Skill 把所有改动写进 Staging。如果代码再把 Skill 中的内容规范全部写成阻断规则，规则就又回到了两处维护。但 Vault 现状说明完全依赖模型自检也不行：09-06 的 Ingest 留下了 6 条断链。

## 决策

Apply 前的检查结果分两级：

**Invariant（阻断）**：违反就会损坏 Vault，与具体 Skill 的写法无关。任一项不通过就禁止 Apply。以 ingest 为例：

1. 写入范围：只能写 `wiki/**`（不含 `wiki/_orphans/**`）、`index.md`、`log.md`、`sources/**`。
2. `sources/**` 只允许改 frontmatter 中的 `ingested-at`，正文与其他 frontmatter 字段必须保持字节级一致。
3. 新建或修改的 `.md` 文件，frontmatter 必须能解析。
4. 本次 Run 新增的 wikilink（新建文件中的全部链接，以及修改后的文件相对 Vault 原版本多出来的链接）都必须能解析到 Vault 或 Staging 中实际存在的文件（`_orphans` 可以作为链接目标）。文件原本就有的链接不检查：Vault 现有的 `log.md` 已包含 9 条无法解析的链接（例如正文举例用的 `[[xxx]]`），如果检查全文，任何追加日志的 Run 都会被永久阻断。
5. `log.md` 只能在原内容末尾追加。
6. 不删除、不移动文件（由 0005 的工具集保证）。

**Warning（提示）**：来自 Skill 的内容规范，违反时在 diff 中标出，由用户在确认时判断。以 ingest 为例：tags 不超过 3 个、每页至少 2 条出链、单次不超过 15 页、Domain 在 Skill 列出的目录内、frontmatter 字段齐全。

## 影响

- 不变量的定义与 Skill 文本相互独立；改 Skill 措辞不需要改代码。
- Warning 的检查项会与 Skill 文本重复，但只影响提示，不影响能否 Apply；Skill 变更后 Warning 跟不上，最坏结果是少一条提示。
- 写入范围随 Task Skill 变化（ingest、lint-fix 各不相同），范围声明放在哪里需要另行决定。
