# 0003 单次运行：确认后写盘，不 commit

- 状态：已接受，部分被 0005 修订（Agent 改为拥有暂存写工具）
- 日期：2026-11-02

## 背景

Vault 现有 `/ingest` skill 包含 8 个步骤：读取 Source、识别概念、查重、写 Wiki Page、回填来源、更新 `index.md`、标记 Source、记录 `log.md`。v1 需要能完整替代一次 `/ingest`，才有实际提效，也才能和现有 skill 公平对比。

## 决策

一次 Ingest 运行只处理一份 Source，流程如下：

1. Agent 只读 Vault，最后提交一份 Proposal。
2. 代码校验 Proposal，并渲染出将要发生的文件变更（diff）。
3. 用户在终端确认。
4. 由代码执行 Apply：写入 Wiki Page、`index.md`、`log.md`，以及 Source 的 `ingested-at`。
5. 不执行任何 git 操作，由用户自行检查后提交。

Agent 没有任何写文件工具；所有写入都只发生在 Apply 阶段。

## 不做

- 批量处理多份 Source。
- 自动 git commit。
- 只出方案、不写盘的 dry-run 模式（可作为调试开关，但不是主流程）。

## 影响

- 用户拒绝时，Vault 不发生任何变化。
- Apply 必须能在写入前检测 Vault 是否在运行期间被改动过（例如你同时在 Obsidian 里编辑），具体策略待定。
