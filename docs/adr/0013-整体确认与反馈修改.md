# 0013 整体确认，可反馈后继续修改

- 状态：已接受
- 日期：2026-11-02

## 背景

一次 Ingest 新建的 Wiki Page 之间互相链接。如果逐文件接受或拒绝，拒掉一页就会在其他页面留下断链，需要重新校验，还可能连锁拒绝更多文件。

## 决策

Finish 校验通过后，终端先展示变更摘要（新建 N 个、修改 M 个文件，Warning 列表），再逐文件展示 diff，然后提供三个选项：

- `y`：执行 Apply（先走 0009 的 hash 核对）。
- `n`：放弃，丢弃 Staging，Vault 不变。
- `r`：输入修改意见，Agent 在同一个 Staging、同一段对话上继续修改，然后再次 Finish、校验、确认。

Revise 与原运行共用 0012 的轮数、时长和费用上限，以及 0007 的 3 次 Invariant 失败额度。时长上限不计入等待用户输入的时间。

## 不做

- 逐文件接受或拒绝。留给以后的审阅 UI。

## 影响

- 意见以用户消息的形式进入对话（Pi 的 `agent.prompt` / follow-up），模型能看到之前做过的全部改动。
- 等待确认期间 Vault 可能被编辑，0009 的核对仍在 Apply 时执行。
