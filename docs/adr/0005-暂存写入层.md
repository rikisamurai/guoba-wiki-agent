# 0005 Agent 通过暂存层写入，全部步骤按 Task Skill 执行

- 状态：已接受，部分被 0019 修订（Agent 可以撤销单个文件的暂存改动）
- 日期：2026-11-02
- 修订：0003 中“Agent 没有任何写文件工具”

## 背景

ingest 的 `SKILL.md` 步骤 4–8 都是写文件操作：写 Wiki Page、回填 `sources`、更新 `index.md`、标记 `ingested-at`、追加 `log.md`。0004 决定规则以 Skill 为准，因此这些步骤也应该由 Agent 按 Skill 执行，而不是在代码里另写一套固定格式。

## 决策

Agent 拥有写工具，但写入只落在内存中的 Staging（暂存层），运行期间 Vault 保持不变。

- 读工具读取的是“Vault + Staging”叠加后的视图：Agent 写入后再读，看到的是自己写过的内容。所有读工具共用同一个视图，不允许出现某个工具读原始 Vault、另一个工具读暂存视图的情况（Haklex 的 staged ID 问题就是反例）。
- 写工具：`write_file`（整文件新建或覆盖）、`edit_file`（替换唯一匹配的字符串）。
- v1 不提供删除和移动。
- 运行结束后，代码对 Staging 与 Vault 做 diff 并校验，用户确认后执行 Apply。

更换 Task Skill（例如 lint-fix、query 反向 ingest）时不需要修改代码，只需要配置它的写入范围。

## 影响

- 0003 的“Agent 无写工具”改为：Agent 只有暂存写工具；Vault 在 Apply 前保持不变这一点不变。
- 机械记账（`index.md` 字母序插入、`log.md` 格式）由模型完成，出错的概率高于代码生成，需要靠校验和确认环节兜底。
- 写入范围与阻断规则需要另立 ADR。
