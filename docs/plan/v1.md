# v1 实施计划

目标：`wiki-agent run <source>` 能按 Vault 中的 ingest Skill 完成一次 Ingest，确认后写盘；每次 Run 留下完整的 Trajectory，可在 `wiki-agent view` 中回放。完成标准见 [ADR 0016](../adr/0016-v1-完成标准与测试分层.md)。

## 依赖关系

```text
M0 骨架 ──┬─► M1 trajectory ─┬─► M3 agent ─► M4 cli run ─┐
          └─► M2 vault ──────┘                           ├─► M6 验收
              M1 ─► M4 cli view ◄── M5 viewer（先出设计）─┘
```

M1–M3 已完成；M5 的界面设计可以在 M1 完成后先行出图。

## 已知风险

| 风险                                               | 来源      | 处理                                                                         |
| -------------------------------------------------- | --------- | ---------------------------------------------------------------------------- |
| 本地开发环境是 Node 22 而非 24                     | M0 验证时 | 代码只用 Node 22.18+ 已支持的能力（原生 type stripping 等）；CI 使用 Node 24 |
| Pi main 分支移除 `Type` 导出                       | ADR 0002  | 工具 Schema 集中在一个模块；升级 Pi 时先跑契约测试                           |
| `deepseek-flash` 不支持中途插入 system 消息        | ADR 0011  | system prompt 在 Run 开始时一次定型；Revise 与校验反馈都以用户消息形式发送   |
| `index.md` 字母序插入靠 `edit_file` 完成，可能出错 | ADR 0010  | 作为 Warning 检查；在 M6 和 v2 评测中观察                                    |
| `AGENT.md` 中被 Run Rules 覆盖的段落仍可能影响模型 | ADR 0018  | 在 Trajectory 中观察，必要时再立 ADR                                         |
